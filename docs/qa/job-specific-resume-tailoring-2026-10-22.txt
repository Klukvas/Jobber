Scope: only the selected job-specific Builder Resume tailoring feature and its necessary atomic creation-quota protection. No next task, commit, push, deploy, schema migration, pricing/billing-rule change, secret-file edit, or adjacent cleanup.

Implemented:
- POST /api/v1/jobs/:id/resume-tailoring generates a server-held proposal with an original 30-minute expiry. Source and Job ownership are checked server-side. Direct JSON contract; no envelope.
- Only explicitly visible summary/experience/skills content is sent to the provider. AI output is validated for allowed target IDs, exact eligible source quotations, output bounds, unique experience edits, existing-skill permutations, and unsupported new numeric / percentage / currency claims. Unchanged suggestions are dropped. Human review remains necessary for the meaning of a paraphrase.
- POST /api/v1/jobs/:id/resume-tailoring/:proposalId/apply accepts only selected proposal IDs and a title. In one PostgreSQL transaction: shared per-user creation lock, current Job/source checks, parent and all section row locks, full source hash comparison, authoritative quota count, complete separate copy, and mutually exclusive Builder Resume Job link. All design settings and hidden sections are copied; the source is never edited.
- Proposal UUID is also the new copy UUID, so its database primary key is a durable commit receipt. Selection/title fingerprint is persisted in Redis before the database commit under the per-user transaction lock. Same-body retry returns the same copy (200); different body or changed Job attachment returns 409; expired proposal returns 410. Failed copy/link transaction leaves no orphan.
- Existing Create, Duplicate, and Import share the same creation lock and transaction-local quota count. Existing ResourceLimit resolves the ceiling before obtaining a transaction connection; no subscription pool query is nested inside a held transaction. Existing import precheck remains.
- Routes are registered even without AI configuration and return AI_UNAVAILABLE (503). Production has no fake-provider toggle. Existing PDF/DOCX exports are reused.
