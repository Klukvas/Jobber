## RB-001 — структурные Undo/Redo не сохраняют восстановление на сервере

**Приоритет:** P1. **Статус:** открыта. **Подтверждение:** первый проход — браузер для удаления → Undo → reload и harness на настоящем коде для отсутствующего remote CREATE. Повторный browser_persistence также проверил Undo добавления Experience и первого добавления Education; результаты и новые доказательства приведены в дополнении ниже и уточняют первоначальное статическое подтверждение этого направления.

**Шаги:** добавить навык и дождаться сохранения; удалить его и дождаться DELETE; нажать Undo; дождаться Saved; перезагрузить страницу.

**Фактически:** строка возвращается на экран, UI показывает Saved, после reload строка исчезает. Harness наблюдает одну локальную строку, ноль строк в модели сервера и ноль вызовов CREATE. **Ожидается:** Undo/Redo изменяет серверную структуру либо явно сообщает, что состояние не сохранено.

**Код:** [useUndoRedo.ts:14](../../fe/src/features/resume-builder/hooks/useUndoRedo.ts#L14) меняет temporal state и dirty-флаг; [resumeDocumentSync.ts:220](../../fe/src/features/resume-builder/lib/resumeDocumentSync.ts#L220) обновляет только известные серверные ID и не создаёт/удаляет строки по разнице структур; [useSectionPersistence.ts:314](../../fe/src/features/resume-builder/hooks/useSectionPersistence.ts#L314) после DELETE забывает серверный ID.

**Доказательства:** [до reload](evidence/resume-builder-2026-10-22/undo-before-reload.jpg), [после reload](evidence/resume-builder-2026-10-22/undo-after-reload.jpg), [harness](evidence/resume-builder-2026-10-22/persistence-harness.txt), [результат 2/2](evidence/resume-builder-2026-10-22/persistence-repro.txt).

**Направление исправления:** согласовывать структурные изменения истории с серверными CREATE/DELETE, корректно учитывать ID и pending-операции; добавить регрессионные сценарии удаления/добавления с Undo/Redo и повторной загрузкой. Исправления не выполнялись.

## RB-002 — CREATE ошибочно отменяется при переключении документов

**Приоритет:** P1. **Статус:** открыта. **Подтверждение:** harness настоящего hook; отдельный браузерный сценарий с искусственной задержкой не выполнен.

**Шаги:** добавить строку в резюме A; оставить CREATE незавершённым; переключить store на резюме B; разрешить успешный ответ CREATE для A.

**Фактически:** hook выполняет DELETE только что созданной строки A, хотя пользователь её не удалял. Harness проверяет фактический вызов DELETE(A, created). **Ожидается:** смена документа сохраняет результат успешной записи A; компенсирующий DELETE выполняется только при явном удалении строки пользователем.

**Код:** [useSectionPersistence.ts:246](../../fe/src/features/resume-builder/hooks/useSectionPersistence.ts#L246) возвращает null для неактивного документа; [useSectionPersistence.ts:289](../../fe/src/features/resume-builder/hooks/useSectionPersistence.ts#L289) трактует null как удаление и запускает DELETE.

**Доказательства:** [harness](evidence/resume-builder-2026-10-22/persistence-harness.txt), [результат 2/2](evidence/resume-builder-2026-10-22/persistence-repro.txt).

**Направление исправления:** отличать смену активного документа от намеренного удаления, хранить pending-create состояние по документу и безопасно принимать поздний ответ. Исправления не выполнялись.
